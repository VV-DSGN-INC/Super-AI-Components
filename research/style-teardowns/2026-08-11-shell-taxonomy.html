App shell taxonomy

How eleven products structure the frame around their content — classified on two independent axes, with the secondary parameters that carry the personality. Companion to the measured style teardown; shell metrics below come from the same live extraction.

The two axes

layout × depth — they vary independently

Axis 1 — chrome layout: where navigation and search live, and whether the content is a region, a sheet, or a column. Axis 2 — surface depth: how regions separate — coplanar (one plane, 1px borders and background tint) vs layered (a tinted canvas with content lifted as sheets: radius + 1px ring + whisper shadow).

Proof they're independent: Asana pairs the most classic chrome (global top bar + dark sidebar) with a layered rounded content sheet, while Monday pairs the same chrome with a fully coplanar surface. And the split archetype exists on both sides: Gmail's three-pane is coplanar; Intercom's is floating sheets.

Layout archetypes

Cockpit

Global top bar spanning full width (search center, create/account at edges) + sidebar beneath. The app is one fixed instrument panel; the page is subordinate. Search is global-first.

Monday · Asana (layered variant)

Console

Sidebar only, no global bar. Content runs full-bleed and owns its header row (title, tabs, actions). Search lives in the sidebar or content header.

OpenAI · Claude Console · Pipedrive · Evernote · ElevenLabs

Framed page

Tinted canvas frame; content floats as one distinct sheet carrying radius + ring. The sidebar sits on the canvas — transparent or tinted, no hard border. "Page on background."

Linear · Twenty · Manus (lite)

Framed split

Same canvas-and-sheet logic, but several sheets side by side (list / detail / context rail), each independently lifted.

Intercom inbox · Twenty record view

Rail + drawer

A slim icon-only rail (~48–72px) for app-level switching plus an inner contextual sidebar. A modifier that composes with any archetype rather than a standalone.

Intercom · Asana · Monday · Slack, Discord

Portal

No sidebar: global header + horizontal tab nav, content as a centered max-width column. Website-like, lightest-feeling shell; scales badly past ~7 sections.

Vercel · GitHub · Basecamp

Focus column

Sidebar + a single centered reading column with the composer anchored at the bottom. Neither full-bleed nor a sheet — a column with generous margins. The default AI-product shell.

ChatGPT · Claude.ai · Manus

Master–detail, coplanar

The flat sibling of the framed split: three panes divided by 1px borders on one plane. The classic mail-client shell.

Gmail · Superhuman · Evernote notes view

Canvas-centric

Content is an infinite canvas; chrome shrinks to floating islands. The logical endpoint of "layered" — everything floats, even the nav.

Figma · Miro · tldraw

Consoles are almost always coplanar and framed layouts are layered by definition — so the genuinely free choices live in the cockpit and split rows, and in how far the layering is pushed.

Secondary parameters

independent of both axes — most of the personality
  • Sidebar finish: dark-branded chrome (Asana; Pipedrive #211c52; Intercom's rail) · tinted paper (Evernote #f6f5f4, Linear #efeff0, Manus #f8f8f7) · coplanar white + border (OpenAI, Claude) · transparent on-canvas (Twenty). Dark sidebars cluster in enterprise/sales tools, tinted in notes/maker tools.
  • Header ownership: global top bar owns title/search (Asana, Monday) vs the content region owns its own header row (everyone else). This is exactly why Asana reads "in between classic and page."
  • Record presentation: opening an item → side peek (Twenty, Notion) · centered sheet over dimmed shell (Linear issues, Intercom's message editor) · full-page navigation (Pipedrive deals). Twenty exposes this as a user setting — "Side panel vs Full page." Invisible in a static screenshot, huge in feel.
  • Nav paradigm: palette-first (Linear — ⌘K is the real nav, the sidebar is a map) vs pointer-first (Asana, Monday). Determines how much sidebar you need at all.

Mapping to our system

theme × finish × shell

Our token architecture already covers two of the three dimensions: the theme axis is color, the finish axis is Axis 2 (elevated ≈ layered, flat-dense ≈ coplanar). The shell is the missing third: a data-shell attribute on the app frame, orthogonal to both, with sidebar finish as a shell prop.

[data-shell="frame"] {
  --shell-canvas: /* --surface-page, one tint step down */;
  --shell-sheet: var(--surface-card);
  --shell-sheet-radius: 13px;          /* our radius scale */
  --shell-sheet-lift: 0 0 0 1px var(--border),
    0 3px 6px -2px rgb(0 0 0 / .02),
    0 1px 1px rgb(0 0 0 / .04);        /* Linear's whisper recipe */
}

Realistic candidates for Pegbo: Console (current prototype), Framed page (the Linear/Twenty test — pure wrapper change, zero component edits), rail + drawer if workspaces multiply, and Focus column for the AI tier. Portal and Canvas don't fit a data-heavy contractor tool.
