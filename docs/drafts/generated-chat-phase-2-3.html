Phase 2. The chat shell answers in parts

O2 chat-shell renders a reply's parts itself and owns the docked view. Opening a view collapses the sidebar to a rail of icons, the view takes the main area and the conversation narrows beside it. In phase 1 the demo had to build this around the shell.

  1. The rail shows icons only, with no clipped labels or empty states.
  2. The Artifacts region shows only once there is an artifact.
  3. A reply that is only a card fills the column.

Phase 3. A view whose body is generated

The view frame stays fixed. Only the body is written, as OpenUI Lang over this registry's own catalog, the same one /openui uses. It renders one line at a time. If a new version fails to render, the frame keeps the last good version, says what failed, and offers Retry.

  1. The model can only name components the catalog exposes.
  2. Each version is kept, so Undo and Retry are always possible.
  3. The program can be shown beside the view, for anyone checking what the model wrote.
